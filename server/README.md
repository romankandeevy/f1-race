# Онлайн

Плана внедрения — в `_materials/f1-online-ru.md`.

## Как играть с друзьями (бесплатно, с этого Mac)

В Терминале, из папки игры (`Сайты/f1-race`):

```bash
npm run online
```

Соберёт игру, запустит игровой сервер (порт 8787) и бесплатный туннель serveo (по ssh, без аккаунта), не даст Mac уснуть
(`caffeinate`) и напечатает ссылки:
- **«В своей Wi-Fi»** — для тех, кто дома в той же сети: быстро, без предупреждений, адрес не меняется;
- **«Через интернет»** — для всех остальных (меняется при каждом запуске и при обрыве туннеля — тогда печатает новую).

Дальше:
1. Открой ссылку сам → **Играть** → **Онлайн** → карточка режима:
   - **Заезд на время** — все на трассе одновременно, болиды-призраки (без столкновений), сессия 5/10/15/20 минут,
     в зачёт лучший круг; начатый до конца времени круг можно доехать; срезка — круг не в зачёт; R — вернуться на трассу.
   - **Гонка** — огни, столкновения, пит-стопы, флаги; свободные места — боты.
   Покажутся код из 4 букв и ссылка-приглашение; там же — трасса, время сессии или круги и боты, свои шины.
2. Друг открывает ссылку. Через интернет первый раз serveo показывает предупреждение — «Continue to Site»; после него
   открывается главное меню: «Онлайн» → ввести код (или открыть ссылку-приглашение ещё раз — со второго раза откроется сразу).
3. Создатель жмёт «Старт». До 12 живых игроков, свободные места — боты.

Выключить — Ctrl+C в том же Терминале.

Варианты:
- `npm run online -- --local` — без туннеля, только своя Wi-Fi.
- Постоянная ссылка через интернет (одна и та же каждый раз): один раз `ssh-keygen -t ed25519` (Enter на всё), потом
  `npm run online -- --name=придумай-имя` — serveo напечатает, как зарегистрировать ключ (вход у них на сайте — это твой
  аккаунт, сделать самому). После регистрации ссылка всегда `https://придумай-имя.serveousercontent.com`.
- Для разработки (игра из `npm run dev`): `npm run server` — клиент на портах 5173/5183/5184 сам ищет сервер на :8787.

Почему serveo: Cloudflare Quick Tunnel на этом Mac не поднимается (системный DNS отдаёт Go-программам пустой список
серверов, а соединение с их сетью не проходит), localhost.run бесплатно даёт ~14 КБ/с — игру (42 МБ) не скачать.

## Как устроено

- `game-server.mjs` — на одном порту раздаёт `dist/` и ведёт гонки по WebSocket `/ws`. Комнаты по коду; гонка —
  `../src/core/race-session.js` (та же физика и боты, что в игре; несколько живых игроков); 240 шагов в секунду; ввод
  игроков окнами по 1/60 с (нет ввода к окну — едет с прошлым); снапшоты 30 Гц (свои полные данные — 10 Гц); таблица 4 Гц.
  Обрыв связи — болид ведёт автопилот, вернулся с тем же токеном (хранится в браузере) — управление снова у игрока.
- `../src/net/online.js` — клиент: лобби, своя машина с предсказанием и откатом к серверу (поправка гасится за 0,1 с),
  чужие — интерполяция с буфером 100 мс (растёт при сбоях), таблица, огни и итог с сервера в виде `race.state`.
- `track-node.mjs` — трасса из GLB без three.js (ось, решётка, пит-лейн, коллизия как в `circuit.js`).
- `../src/net/wire.js` — двоичный снапшот машин (30 байт на болид) и машины безопасности; свою машину сервер шлёт
  отдельно JSON 10 раз в секунду (состояние для отката, потолок скорости под флагами, табло флагов).
- Флаги на сервере — те же `flags.js`, `safetycar.js`, `tow.js`, что в одиночной гонке (с пустой сценой): жёлтые, VSC,
  машина безопасности, красный флаг с рестартом, эвакуатор, отказ мотора у бота. Клиенту — события (`ev`) и положение
  машины безопасности; эвакуатор клиент рисует сам по событию (тайминг тот же), сервер убирает болид из снапшотов.
- `../src/core/quali-session.js` — онлайн-заезд на время: призраки, таймер сессии, лучший круг, доезд начатого круга
  (до 3 мин), срезка снимает круг, разбитый болид заменяется. Без ботов. Те же методы, что у race-session.
- Сборка болида (`../src/build.js`): игрок присылает сборку из гаража и настройку болида в профиле (`hello`/`name`), изменения настройки по ходу — сообщением `setup`. Опция комнаты `builds`: `own` — у каждого своя сборка, у ботов случайные; `same` — у всех стандартный болид (настройка своя). Чужое и дороже бюджета сервер заменяет стандартом (`cleanBuild`, `cleanSetup`).
- `start-online.mjs` — сервер + туннель + caffeinate одной командой, печатает ссылки.
- Проверки: `online-check.mjs` (два клиента без браузера: комната, код, шины, старт, ввод, снапшоты, обрыв и возврат),
  `flags-check.mjs` (заглох бот → инцидент → машина безопасности → эвакуатор → зелёный), `quali-check.mjs` (заезд на время:
  два игрока на ИИ, таблица, доезд, конец), `race-check.mjs` (повтор гонки
  до бита), `build-check.mjs` (сборки и настройка игроков в обеих сессиях, боты со сборками, опция комнаты). Сервер с `--debug` принимает команду «заглушить мотор» (`{t:'debug', code, fail}`) — для проверок в браузере.

Замеры (30.10, локально): снапшоты 30,0 Гц, ввод подтверждается 597–598 из 600 окон, трафик **21,5 КБ/с** на игрока
(было 62 в JSON, потом 35; цель плана ≤ 20), шаг гонки на 12 болидов ~0,3 мс. В браузере: своя машина
по предсказанию, средняя поправка 0,3 см, одна 92 см (контакт с соседом — предсказание соседей не знает).
Через туннель serveo: игра и WebSocket работают, модель болида 3,7 МБ — 3,5 с (Марина 25 МБ — ~25 с у друга).

## Лаборатория (этапы 1–2)
### Что есть

- `lab-server.mjs` — сервер на `ws`: каждый игрок в своём мире физики (`../src/vehicle.js`, шаг 1/240 с), шагает по окнам ввода (1/60 с), снапшоты 30 Гц. Очередь ввода `--jb` окон (по умолчанию 8 ≈ 133 мс).
- `netmodel.mjs` — канал как у TCP: потеря пакета = переотправка (250 мс) и задержка всех следующих. Параметры: `--delay`, `--jitter`, `--loss`.
- `netsim.mjs` — ошибка отображения чужих машин без браузера (ворота этапа 1).
- `predict-check.mjs`, `client-check.mjs` — ошибка предсказания своей машины (ворота этапа 2) без браузера.
- `bot-client.mjs` — второй игрок без окна, для проверки в браузере.
- Клиент: `../net-lab.html` + `../src/net/` (`interp.js` — интерполяция чужих, `predict.js` — предсказание своей, `state.js` — состояние болида для отката, `netlab.js` — страница).

### Как запустить

```bash
cd server
node lab-server.mjs --port=8787 --delay=20 --jitter=5 --loss=0.02 --jb=8
```

В браузере (dev-сервер проекта, `npm run dev`): открыть `http://localhost:5183/net-lab.html?ws=ws://localhost:8787` в двух окнах. Ввод — W/S/A/D.

Проверки без браузера:

```bash
node netsim.mjs --seconds=40
node predict-check.mjs --delay=6 --inputDelay=3
node client-check.mjs ws://localhost:8787 20
```

### Что показали проверки

- Интерполяция чужих (`netsim`, буфер 100 мс): при 2% потерь p95 ≈ 0,09–0,16 м, но худший кадр до 6 м. С адаптивным буфером (+60 мс на сбой) худший кадр 0,02–0,05 м, экстраполяция 1–3% кадров. При 5% потерь и плохой сети без адаптивного буфера p95 ≈ 2 м.
- Предсказание своей машины, модель в Node (`client-check`): поправки 0,00 см при задержке 20–60 мс, джиттере до 40 мс и потерях до 5%. Ключ — синхронизировать внутреннее состояние болида, включая износ, температуры и мотор (`state.js`); без износа поправки были до 10 м.
- Предсказание в браузере (WebKit на Mac, сервер на Node): средняя поправка ≈ 1,2 см, редкие поправки до 2 м. Причина — расхождение последних бит между движками (`Math.atan2` в WebKit и V8 отличается на ~1e-15), которое Rapier усиливает. Это не решено: вопрос на следующий шаг (см. план).

## Этап 3: гонка на сервере (без картинки)

Ядро гонки — `src/core/race-session.js`: огни старта, боты, круги, границы трассы, пит-стоп (заказ и автопилот у въезда), стюарды (контакты, наказания), сход, чёрно-оранжевый флаг, классификация. Одна гонка — один мир физики и один ГПСЧ (`src/core/rng.js`, seed). Трасса на сервере — `track-node.mjs`: читает GLB напрямую (без three.js), те же имена деталей и та же коллизия, что в `circuit.js`.

Общие модули (`bots.js`, `start.js`, `vehicle.js`) получили необязательные параметры: визуал (`car`, `scene`) и ГПСЧ (`rand`). В браузере ничего не меняется — по умолчанию работают прежние вызовы.

Проверка (ворота этапа: повтор записи ввода даёт тот же итог, расхождение 0):

```bash
node race-check.mjs --laps=2
node race-check.mjs --laps=5
```

Скрипт ведёт гонку ботов и игрока (водитель ИИ), пишет его ввод, потом гонит заново с тем же seed и по записи, и с другим seed (контроль). Итоги сравниваются целиком (места, круги, штрафы, статусы).

Результаты:
- 1 круг, seed 7: все 12 доехали, итог повторяется; воспроизведение по записи совпадает; другой seed даёт другой итог.
- 2 круга: то же самое.
- 5 кругов (с пит-стопами ботов): сначала расхождение — пит-стоп брал `Math.random`; после передачи `rand` в `createPitStop` (боты и игрок) итог повторяется, воспроизведение по записи совпадает, другой seed — другой итог. Игрок (водитель ИИ) в пит не заезжает и получает дисквалификацию по правилу двух составов — это ожидаемо для проверки.

Пока не покрыто: флаги, машина безопасности, эвакуатор, красный флаг (этап 3б, логика завязана на картинку в `main.js`). Один процесс — одна гонка: `hullOwners` в `vehicle.js` общий (сессия чистит его при создании).

## Что не сделано

- Предсказание своей машины не знает соседей: при контакте поправка до метра (гасится за 0,1 с, больше 3 м — сразу).
  Это свойство схемы (соседи на экране — в прошлом на 100 мс), не баг.
- В браузере (WebKit) поправки изредка больше, чем в Node: последние биты `Math.atan2` различаются между движками.
- Через интернет ссылка не постоянная без регистрации ключа у serveo (см. выше — это твой аккаунт); предупреждение serveo
  при первом заходе убирается только у них платно.
- Тест с мобильного интернета в РФ и настоящая гонка 12 живых — нужны живые люди.
